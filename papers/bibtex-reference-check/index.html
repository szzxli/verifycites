How to check a BibTeX file for references that don't exist

A .bib file can compile cleanly and still hold entries nobody can find. Here is how to check every entry before you submit.

Check a .bib file
§1

Why a clean compile isn't enough

LaTeX and BibTeX check that an entry is well-formed. They never check that the work behind it exists.

A .bib file grows over years. Entries get copied from old projects, from a co-author's file, from a search result, or typed in by hand late at night. BibTeX will happily format an entry whose title was never published, whose DOI opens a different paper, or whose authors and year belong to something else. Nothing warns you until a reviewer or examiner tries to look it up.

The fix is simple: before you submit, look up every entry you actually cite and confirm it points to a real record with the same title, authors and year.

§2

Check your .bib file in a few minutes

The free /papers checker reads a .bib file directly. No account, nothing to install.

  1. Get the file you actually cite from. In Overleaf, open the .bib file and copy its contents, or download the project and take the .bib from it. If you use a reference manager, export the collection for this paper as BibTeX. Checking only the entries in this paper is faster than checking your whole library.
  2. Open the /papers checker and click Upload .docx / .pdf / .bib, or paste the file's contents into the text box. Pasted text that starts with an entry such as @article{ is read as BibTeX.
  3. Click Check citations. Each entry is looked up by its DOI or arXiv ID when it has one, and by its title and authors when it doesn't.
  4. Work through anything that isn't plainly found. Each result is shown by citation key (for example @smith2021) with a label and a next step, so you know which entry to open in your editor.

The checker reads @string macros and skips @comment and @preamble. If two entries share a citation key, the second one is skipped and listed as a duplicate key, which is worth fixing anyway.

§3

What the results mean

For each entry, the checker looks for an existing record in public registries (Crossref, DataCite/arXiv, OpenAlex, Europe PMC, DBLP; Semantic Scholar as a last resort), checks that the DOI or arXiv ID matches that record, compares the title, author surnames and year, and flags retracted papers. The labels you are most likely to see:

  • Found. A matching record exists. Nothing to do for existence.
  • Found, but details don't match. A record was found, but the title or authors differ, or the year is off by more than one. Usually the entry mixes up two papers or has a typo. Compare it with the record and fix the entry.
  • ID_NOT_FOUND / ID_NOT_FOUND_TITLE_FOUND. The DOI or arXiv ID in the entry has no record. If a title search found a record, the identifier is probably mistyped. Copy it again from the publisher or arXiv page.
  • INVALID_DOI. The doi field isn't a well-formed DOI, so it was not looked up. Fix it or remove it.
  • UNVERIFIED. No confident match. Add a DOI or arXiv ID if the work has one, or search for it by hand. Don't keep it as-is.
  • NOT_A_SCHOLARLY_RECORD. The entry looks like a web page, software or a standard, which usually has no registry record. Open it yourself.
  • RATE_LIMITED. A registry couldn't be reached. This says nothing about the entry. Try again later.

A year off by one stays Found; it is usually the preprint versus the published version. A field missing from your entry or from the record is shown as Not compared, with the reason.

§4

What a .bib check does not tell you

  • A .bib file has no claims, so the checker reports record, identifier and field results only. It does not check whether a source supports what you wrote. To do that, read the source. (If you paste a full draft instead, an optional screen can compare a claim with the cited paper's abstract only.)
  • It does not compare venue, volume, issue or pages, and authors are compared by surname only.
  • It is not a formatting checker. It won't fix capitalization, missing braces in titles, or your bibliography style.

“Not found” is not proof that a work does not exist. A real paper can be missing from the free indexes, especially older books, theses and local reports. Use the results to decide which entries to open and check by hand.

§5

FAQ

Is my .bib file uploaded anywhere?
No. The file is read in your browser. Only citation identifiers and reference text are sent to the public registries for the lookups.

Does it work with a .bib exported from Zotero, Mendeley, JabRef or Overleaf?
Yes. It reads standard BibTeX entries, whatever tool wrote them. There is a separate guide for exporting from Zotero.

Can I check a .bib file automatically on every commit?
Yes. If your paper lives in a Git repository, the open-source VeriPaper project has a command-line tool and GitHub Action for checking .bib files.

My university already runs Turnitin. Isn't that enough?
Turnitin compares text; it doesn't look up whether your sources exist. See Does Turnitin check whether your references exist?

Does it cost anything?
No. The checker is free and open source.
